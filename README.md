# Antipode · 对跖点

> TECHATHON 2026 · 融合信息软件
>
> 它把你关注的信息收进「仓库」，再自动为你建一个「**反仓库**」——
> 存放那些你**没看见、但值得看见**的信息。

---

## 这个仓库怎么读

仓库按**拼接单元**组织：每一侧一个顶层目录，各自完整、能独立跑；
拼接时只按接口对接，不需要读对方的实现。

| 目录 | 归属 | 负责什么 | 状态 |
|---|---|---|---|
| [`first/`](first/) | 我们这一侧 | ① 网址 + 账号 → 建库　② 库条目 → 判立场 → 找对立面 → 六道闸门 → 写反库 | ✅ **已就绪** |
| [`second/`](second/) | 队友那一侧 | 判兴趣、分类模型、信息流排序 | 待并入（目录已就位） |
| [`materials/`](materials/) | 参赛材料 | 路演 PPT、答辩看板、提交材料、演示视频脚本、赛事规则 | 不参与开发，别动 |

> 入口变了：客户不给整理好的链接，给的是**一个主页网址 + 账号**（抖音 / 微博 / GitHub）。
> 所以 `first/` 现在也含第一段采集 —— 怎么登、哪个平台稳，见
> [`first/docs/账号采集_说明.md`](first/docs/账号采集_说明.md)。

**要拼接，看 [`first/INTEGRATION.md`](first/INTEGRATION.md)** —— 输入输出契约、三种接法、
五个易踩的坑、验收清单，都在里面。

## `first/` 里有什么

| | |
|---|---|
| **入口** | [`first/AGENTS.md`](first/AGENTS.md) —— 给接手的人 / 编码 agent 的一页指令（60 秒上手、接口速查、铁律、不要做的事） |
| **采集** | `code/collect_account.py` —— 账号 + 网址 → 库（GitHub 走 API，其它走浏览器） |
| **引擎** | `code/` —— 零第三方依赖，Python 3.9+ 直接跑（浏览器采集也只靠标准库 + CDP） |
| **接口** | `python code/app_api.py`（桌面应用：平台/库/开关）与 `python code/server.py`（单条 `POST /antipode`），都只监听本机 |
| **数据** | `data/` —— **真跑出来的**库与反库（知乎 10 条 / 16 条反信息，GitHub 5 条），可直接当界面 mock |
| **文档** | `docs/` —— 应用集成、账号采集、流水线说明、立场抽取、检索实测、字段契约（只放做软件要用的） |
| **演示** | `docs/反库演示.html`（双击就开、断网可用）—— 写界面时可当视觉参照 |
| **参赛材料** | [`materials/`](materials/) —— 路演 PPT、答辩看板、提交材料、演示视频脚本、赛事规则。**与代码无关，不放进 `first/`** |

## 两条不能让步的规则

1. **LLM 只负责「提出问题」，答案必须来自真实检索。**
   反库每一条都有可点开的 URL —— 没有出处的内容一律不写。
2. **对立面不是「感觉相反」，是符号运算。**
   `takes_side == opposite(原条目.supports)`，没有"大致相反"。

> 由此带来一个必须接受的结论：**「没找到反信息」是正常判定，不是失败。**
> 中立陈述、议题不在表内、候选全被闸门拒掉 —— 系统会明确告诉你原因，而不是凑一条给你。
