六、我们知道自己会错在哪

  • 中文语料有时真的没有反面声音
    TDD、远程办公两个议题跑完整库产出 0 条。这不是没跑通，是语料里确实没有站得住的反面文章 —— 我们选择空着，不硬凑。
  • 教程帖仍可能被当成观点
    《vue3 源码解析》这类"教程里顺带一句评价"的内容，规则和阈值都不好切，已知会漏。
  • 站点可达性不稳
    V2EX 官方站在本机 502；知乎 403、公众号要 JS 渲染；CSDN 会间歇性 521（已做退避重试）。抓不到就明确报「抓不到」，绝不编正文。
  • 立场抽取不是 100%
    评测集 90.2% 四分类准确率。判错时反库会跑偏，所以每一条都要人眼可回原文核对。
  • 评测本身有噪声
    同一 prompt 连跑两次，失败条目会变 —— 服务端缓存把不确定性伪装成了确定性，这个坑我们记下来了。

七、可能被问到的问题

会不会变成抬杠机器？
不会。三道硬约束：必须有论证结构、必须有可验证出处、必须过对立度阈值；排序里「论证质量」和「对立度」各占 40%，抬杠拿不到分。
反库里会不会编东西？
不会。LLM 只负责「提出问题」，答案必须来自真实检索，每条都带 URL + 原文证据子串，证据不在原文里直接丢弃。AI 自编那一档默认关闭。
为什么有时候没有反信息？
四种情况，看板里逐条可查：链接抓不到 / 原文没有明确立场 / 检索到候选但全被闸门拒 / 议题不在表内。空着比硬凑一条更有用。
反推荐会不会很烦人？
它默认是关的，按库开启（antipode_enabled）。邮件、代码 issue 这类私人事务本来就不该开。
为什么不全用模型判？
模型判「这场争论里你站哪边」很强（90.2%），但判「这条内容是不是跑错场子」很弱 —— 同形异义这类错误交给确定性规则更便宜也更可解释。
队友的库只给链接怎么办？
我们自己取正文（CSDN / GitHub / 少数派 / 普通博客实测可抓），取不到就明确报失败；用户授权后可带自己的登录态读他本来就有权看的文章。
