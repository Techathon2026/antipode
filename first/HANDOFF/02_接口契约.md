# 02 · 接口契约（桌面应用后端）

> 目标形态：左侧菜单加一栏「我的信息平台」→ 用户自己添加平台（知乎 / GitHub …）
> → **每个平台一个库** → 点进去看他筛过的信息 → 合适的信息带反推荐 → **反推荐可按库开关**。
>
> 后端已经写好并跑通：`code/app_api.py`。这篇是接线说明，不是构想。
> 本文件里的每个 JSON 都能在 `examples/` 找到**真实返回**的原件。

---

## 1. 一句话架构

```
桌面应用（Electron / Tauri / 其它）
   ├─ 左侧菜单新增「我的信息平台」
   ├─ 页面调本地后端  http://127.0.0.1:8790
   └─ 后端 code/app_api.py
         ├─ 采集：collect_github.py / collect_zhihu.py / collect_account.py / build_vault.py
         ├─ 建库：build_vault.py（判立场、写省流）
         └─ 反推荐：run_vault.py（按库开关决定跑不跑）
```

**为什么是本地 HTTP，而不是把 Python 塞进主进程**
- 三条采集链路都要起浏览器、要长任务（知乎 10 条约 15 分钟）、要断点续跑，天生适合独立进程；
- 崩了不拖垮界面，重启后端即可恢复（状态落在 `data/platforms.json`）；
- 将来换成队友的库/模型，只改后端，界面一行不动。

**为什么不用 `code/server.py`**
`server.py` 是给队友的单条能力接口（一条 URL → 一条反库条目），**只读、无状态**。
桌面应用要的是**状态**：加了哪些平台、每个平台一个库、这条有没有反推荐。两件事混一起会互相牵制，所以分成两个进程。

---

## 2. 启动

```bash
python code/app_api.py                # 默认 127.0.0.1:8790
python code/app_api.py --port 8790 --host 127.0.0.1
```

- 零第三方依赖，Python 3.9+ 即可
- 已开启 CORS（`Access-Control-Allow-Origin: *`），渲染进程可以直接 `fetch`，**不需要代理**
- ⚠️ 只适合本机：现在没有鉴权。**不要把 `--host` 改成 0.0.0.0** 当作对外服务
- 就绪探测：轮询 `GET /health` 返回 200 再显示页面

## 3. 数据三层（先认清这个，接口就好懂）

### 3.1 库（Vault）= 用户能理解的单位 = 一个平台

```json
{ "vault_id": "zhihu-1017T2051", "topic": "知乎 · 搜索「微服务」",
  "antipode_enabled": true, "counter_types": ["opposing_view"],
  "created_at": "...", "built_by": "collect_zhihu.py", "source": "zhihu",
  "item_count": 10, "antipode_eligible_count": 9 }
```

### 3.2 库条目（Vault Item）

界面上真正显示的东西。**关键字段只有 6 个**，其余是审计用的：

| 字段 | 类型 | 界面怎么用 |
|---|---|---|
| `id` | str | 主键，反库条目靠 `for_vault_item` 指向它 |
| `title` | str | 标题 |
| `url` | str | 「打开原文」 |
| `summary` | str | 卡片正文（中文省流，**不是立场判断**） |
| `antipode_eligible` | bool | **这条内容适不适合找反面**（条目级！） |
| `antipode_reason` / `eligibility_reason` | str | 不适合的原因，挂 tooltip |

其它：`source`、`kind`（`opinion` / `reference` / `video` …）、`text_chars`（正文长度）、
`full_text`（正文，判立场用，**界面不必展示**）、`junk_check`、`stance_dropped`（判错被丢弃的立场，审计用）。

> 真实样例：`data/vault_zhihu-1017T2107.items.jsonl`、`data/vault_github-new-1017T2025.items.jsonl`

### 3.3 反库条目（Antipode Item）

**独立存放**，不与库条目混放，靠 `for_vault_item` 建立对应。

| 字段 | 含义 |
|---|---|
| `id` / `for_vault_item` | 自己 / 指向的库条目 |
| `issue_id` | 属于哪个二元议题（如 `microservices_vs_monolith`） |
| `takes_side` | **它站的边**（必须 = 原条目的反面，符号运算得出的） |
| `counter_type` | `opposing_view`（观点对立）/ `counter_evidence`（反向证据，预留）/ `blind_spot`（视野缺失，预留） |
| `url` / `evidence_url` | 真实链接。**`synthesized=false` 时一定存在** |
| `title` / `summary` / `raw_excerpt` | 卡片内容 |
| `evidence_span` | 原文里支撑「它站这边」的那一段 —— 「回现场」用 |
| `opposition_score` | 对立度（0–1，阈值 0.7） |
| `argument_score` | 论证质量（`null` = 本期未打分，**界面别显示 0 分**） |
| `synthesized` | **true = AI 自编，没有真实出处，必须视觉区分**（默认关闭） |
| `gate` | 闸门记录：过了哪几道、证据来源、模型后端 |
| `found_by` | 怎么找到的：`stage`（`origin`/`global`/`synthesized`）、`source`、`query` |

> 真实样例：`data/antipode_zhihu-1017T2051.jsonl`

## 4. 接口全量（7 个）

> 全部返回 `{"ok": true|false, ...}`；错误时 `{"ok":false,"error":"中文原因"}`。
> 真实响应见 `examples/01_health.json` … `examples/07_不存在_404.json`。

### 4.1 `GET /health` — 能力清单

界面「添加平台」页的能力表就用它，**不要在前端硬编码平台列表**。

```json
{ "ok": true, "service": "antipode-platforms", "version": "0.1",
  "platforms": {
    "github": {"label":"GitHub","auth":"可选：只读 token（不填会读本机已有凭据）","antipode": false},
    "zhihu":  {"label":"知乎","auth":"第一次需要弹窗登录（登录态存在本机，之后不用再登）","antipode": true},
    "douyin": {"label":"抖音","auth":"第一次需要弹窗登录（视频正文短，多数只归档）","antipode": false},
    "weibo":  {"label":"微博","auth":"第一次需要弹窗登录","antipode": false},
    "url":    {"label":"链接","auth":"不需要登录（公开文章）","antipode": true}
  },
  "notes": "只监听本机；不存密码；登录态不出本地" }
```

`antipode` = 这个平台**能不能**开反推荐。`false` 时开关要置灰并显示 `auth`/说明。

### 4.2 `GET /platforms` — 我加了哪些平台（首屏卡片）

```json
{ "ok": true, "count": 2, "platforms": [{
    "id": "zhihu-1017T2051", "platform": "zhihu", "label": "知乎 · 微服务",
    "input": "微服务", "limit": 10, "days": 7, "lang": "",
    "antipode_enabled": true, "status": "done",
    "item_count": 10, "eligible_count": 9, "antipode_count": 16,
    "last_stage": "完成：10 条信息，9 条可反推荐，16 条反信息",
    "last_run": "2026-10-17T21:01:00+08:00", "last_error": "",
    "antipode_supported": true }] }
```

卡片建议显示：`label` + `item_count` + `eligible_count` + 开关状态 + `last_stage`。
**`token` / `cookie` / `password` 永远不会出现在返回里**（`_public()` 主动剥离）。

### 4.3 `POST /platforms` — 添加平台（异步开跑）

```json
{"platform": "zhihu", "label": "知乎 · 我关注的", "input": "微服务",
 "limit": 10, "antipode_enabled": false}
```
→ `201 {"ok":true,"platform":{...},"job":{"id":"j-xxxxxxxx","status":"running"}}`

| 字段 | 必填 | 说明 |
|---|---|---|
| `platform` | ✅ | `github` / `zhihu` / `douyin` / `weibo` / `url` |
| `id` | | 不给就自动生成 `<platform>-<6位>`；**给的话必须唯一**（重复 → 409） |
| `label` | | 卡片显示名，默认平台名 |
| `input` | | 语义按平台变，见下表 |
| `limit` | | 最多几条，默认 10 |
| `days` | | 仅 GitHub：最近几天的新项目，默认 7 |
| `lang` | | 仅 GitHub：只看某语言（`python`） |
| `token` | | 仅 GitHub：只读 PAT。**只在本地落盘，不返回前端** |
| `antipode_enabled` | | 默认 **false**；对不支持的平台传 true 会被静默降为 false |

`input` 各平台含义：

| platform | input | 认证 | 反推荐 |
|---|---|---|---|
| `github` | 留空 = 最近 N 天最热新项目；填 `python` = 只看该语言 | 可选只读 token | ❌ 仓库没有立场 |
| `zhihu` | 议题关键词（如「微服务」）；**留空 = 热榜（只做收集）** | 第一次弹窗登录 | ✅ 观点长文 |
| `douyin` / `weibo` | 主页链接（留空 = 打开平台首页让人自己进） | 第一次弹窗登录 | ❌ 正文太短 |
| `url` | 一串文章链接，一行一个 | 不需要 | ✅ 观点文章 |

### 4.4 `GET /jobs/{id}` — 采集进度（前端轮询 2–3 秒）

```json
{ "ok": true, "job": {
    "id": "j-1a2b3c4d", "platform_id": "zhihu-1017T2051", "kind": "collect",
    "status": "running",            // running | done | failed
    "stage": "正在为 9 条适合的内容找反面",
    "progress": ["找到 10 条，开始取正文…", "…"],   // 最近 200 行原始输出
    "result": {"items": 10, "eligible": 9, "antipode": 16},
    "error": "", "started_at": "…", "finished_at": "" } }
```

- `stage` **本来就是给人读的中文**，直接显示，不要再包装。
- `progress` 收进「查看详情」，别铺在主界面。
- **实测耗时：GitHub 约 15 秒；知乎 10 条（含判立场 + 反推荐 9 条）约 15 分钟。**
  → **前端必须做进度条，否则用户会以为卡死。** 建议首次引导文案就写「这一步要等十几分钟，可以先干别的」。
- `status: done` 但 `result.antipode == 0` 可能是正常的（见 5. 分支）。

### 4.5 `GET /platforms/{id}/items` — 这个库里筛出来的信息

查询参数：`only=all|eligible`（默认 all）、`q=关键词`（在 title/summary 里搜）

```json
{ "ok": true, "count": 9, "items": [{
    "id": "u-e41d0fcc90", "title": "微服务入门这一篇就够了",
    "url": "https://zhuanlan.zhihu.com/p/381847108",
    "summary": "微服务架构通过服务注册中心和配置管理解决单体应用的扩展…",
    "kind": "opinion", "text_chars": 10259,
    "antipode_eligible": true, "antipode_reason": "",
    "antipode": [{
        "title": "从微服务走向单体化", "url": "https://www.v2ex.com/t/1106152",
        "takes_side": "单体", "opposition_score": 0.95,
        "summary": "CEO 因微服务部署复杂，要求合并服务简化…",
        "evidence_span": "CEO 觉得微服务部署极其繁琐…",
        "synthesized": false }] }] }
```

注意：这里做了**裁剪与改名** —— 返回 `text_chars`（取 `text_chars` 或 GitHub 的 `readme_chars`），
不返回 `full_text` / `gate` / `found_by`。需要审计信息请直接读 `data/*.jsonl`。

### 4.6 `PATCH /platforms/{id}` — 开 / 关反推荐（按库）

```json
{"antipode_enabled": true}
```
- `200 {"ok":true,"platform":{...},"changed":["antipode_enabled"]}`
- 对不支持的平台打开 → **400**，`error` 就是给用户看的解释：
  `{"ok":false,"error":"GitHub 只做信息收集：仓库没有「对立面」"}`
- 也可改 `label` / `input` / `limit`

**关掉不是「隐藏」，是「不生成」**：`run_vault` 读库里这个字段，关着会直接拒绝生成。
用户的选择应该体现在产物上，不是 UI 遮罩。

### 4.7 其它

| 接口 | 作用 | 状态码 |
|---|---|---|
| `GET /platforms/{id}` | 单个平台详情 | 404 |
| `POST /platforms/{id}/refresh` | 重新采一次（异步，返回 job） | 202 / 404 |
| `DELETE /platforms/{id}` | 移除平台，**连带删掉这个库的 3 个文件** | 200 `{"removed":[...]}` / 404 |
| `GET /` | 接口清单（调试用） | 200 |

## 5. 前端只有四个分支（照着写就不会错）

| 条件 | 界面 |
|---|---|
| `antipode_eligible = false` | 只显示摘要 + 原文链接，**不给「看反面」按钮**；`antipode_reason` 挂 tooltip |
| `antipode_eligible = true` 且 `antipode` 非空 | 显示反推荐卡片（可折叠：标题 + 站哪边 + 原文证据 + 打开原文） |
| `antipode_eligible = true` 但 `antipode` 为空 | 「这条暂时没找到合格的对面」——**不是错误，不要显示红字** |
| `synthesized = true` | **必须视觉区分**（灰底 / 角标 / 「AI 生成，无出处」），因为它是唯一没有真实 URL 的东西 |

另外两个界面决定（不是随便定的）：

1. **一个平台 = 一个库**，不是一个平台 = 一堆条目。库 id 就是 `platform.id`，文件名 `vault_<id>.json`。
2. **不可反推荐的条目也要显示**，并给原因 ——「今天这 10 条里只有 1 条值得找反面」本身就是信息。

## 6. 接线（Electron 为例）

```js
// 主进程：后端进程管理（启动时 spawn，退出时 kill，崩了重启）
const { spawn } = require('child_process')
const backend = spawn(pythonExe, [apiJs, '--port', '8790'], { cwd: apiDir, windowsHide: true })
backend.on('exit', (code) => { if (code !== 0) scheduleRestart() })

// 渲染进程：直接 fetch，CORS 已开
const r = await fetch('http://127.0.0.1:8790/platforms').then(r => r.json())
```

要点：
- **不要**在 `preload` 里做 HTTP 转发（多此一举，CORS 已开）。
- 轮询 `job` 时定时器要在组件卸载时清掉，`status !== 'running'` 就停。
- 「添加平台」成功后立刻跳到详情页并挂上轮询 —— 用户看到第一条结果前不要让他以为没反应。
- 后端未就绪时先显示骨架屏，不要在 UI 上暴露 `ECONNREFUSED`。

## 7. 打包成 exe 的坑（**先看这段，能省一个下午**）

`app_api.py` 是靠 `subprocess` 调同目录的 `collect_*.py` / `run_vault.py` 来干活的。
**PyInstaller 打成单文件 exe 之后，`sys.executable` 指向的是那个 exe 而不是 python**，
再 `subprocess([sys.executable, "collect_zhihu.py", ...])` 会把 exe 自己当解释器重新拉起来 → 直接崩。
单文件方案还要处理 `sys._MEIPASS` 解包目录里的脚本路径，改造成本远超收益。

**推荐方案（省事、可现场调试）：随应用分发一个 embeddable Python + 整个 `code/` 目录**

```
<安装目录>/
├─ 你的应用.exe
├─ runtime/python.exe          ← Windows embeddable package，约 15 MB，解压即用
└─ antipode/
    ├─ code/                   ← 原样拷过去
    └─ data/                   ← 数据目录（也可以指到 userData，见下）
```
然后用 `spawn(runtime/python.exe, ['antipode/code/app_api.py', '--port', '8790'])`。

**数据放哪**：建议 `<userData>/antipode/data/`，别放安装目录（`Program Files` 没写权限）。
`app_api.py` 里 `_DATA = os.path.join(_FIRST, "data")`，改成可配置（环境变量 `ANTIPODE_DATA`）是一行的事。
**改完记得同步 `_STORE` 与 `vault_paths()`** —— 三处必须指向同一个目录，否则「加了平台但读不到条目」。

## 8. 现场演示顺序（这个顺序是验证过的）

1. **GitHub**（快、稳、不用登录，约 15 秒）→ 证明「加平台 → 出库 → 点开看省流」
2. **知乎按议题**（要登录、要等）→ 证明「同一条信息下面真的挂着对面」
3. **关掉反推荐开关 → 重新采集 → 反库不再生成** → 证明「开关是真的」，这一下最有说服力

> 演示前先跑一次知乎，把登录态和模型额度都热好；现场不要用「热榜」演示反推荐（见 `01_现状与边界.md` 第 5 节）。

## 9. `examples/` 索引

| 文件 | 内容 |
|---|---|
| `01_health.json` | 5 个平台的能力清单 |
| `02_平台列表.json` | 两个平台（知乎开、GitHub 关）的卡片数据 |
| `03_条目_知乎_只含可反推荐.json` | `?only=eligible` 的 9 条，每条带 1–2 条反信息 |
| `04_条目_GitHub.json` | GitHub 库：`antipode_eligible` 全 false，`antipode` 全空 |
| `05_开关被拒_400.json` | 给 GitHub 开反推荐被拒的真实提示 |
| `06_开关成功_200.json` | 给知乎开反推荐的返回 |
| `07_不存在_404.json` | 错误响应形状 |

每个文件都是 `{"_说明","_请求体","_状态码","_响应"}` 四段式，`_响应` 是**服务端原样返回**。
