## 1. 技术坑（结论级，别再试）

### 1.1 议题不能「硬凑」——这是这个项目最容易走歪的地方

判立场时，模型很愿意给任何一篇文章安一个议题。早期版本因此把「如何评价 DeepSeek 新模型」
判成「AI 助手削弱开发者」，然后在检索里找到一堆无关对立面。

修复（三处，缺一不可）：
1. 判出的议题必须在原文里**真实命中**关键词，全表 0 命中 → 不标 ★（`collect_zhihu` 的议题依据闸门）；
2. 命中数很弱（1 次）且没有更强候选 → 判「不沾边」，不放行；
3. 梗类议题（`tabs_vs_spaces`、`tofu_pudding`）在 `NO_RETRIEVAL` 里，**直接不进检索链路**，
   抛 `RuntimeError` 后映射成 `no_issue`，而不是当成「没找到」。

> **不要为了让 ★ 变多而放松这三处。** ★ 率从 90% 掉到 30% 不是退步，是终于不说谎了。

### 1.2 同形异义：字面命中 ≠ 讨论的是这场争论

「过度依赖辅助驾驶」命中了「AI 助手」，但不是「AI 编程助手」那场争论；
「自建 CDN」命中了「自建」，但不是「自建 vs 上云」。

解决：`retrieval_terms.TOPIC_GUARD`，**标题优先的两级判断**。
⚠️ **不要去改 `SYSTEM_PROMPT`** —— 一改，90.2% 的评测基线就作废了；
通用解（让模型回答「这两段是不是同一场争论」）留待以后做，现在用规则拦住更稳。

### 1.3 省流版不能用来判立场

`summary` 只用来**定位议题**。判立场必须用 `full_text`：
省流会把作者态度抹平（"作者认为 X 有明显问题" → "文章讨论了 X"）。
所以省流的 prompt 里明确**禁止做立场判断** —— 否则摘要会替用户先选好边。

### 1.4 浏览器自动化（CDP）三个必踩的坑

| 坑 | 现象 | 结论 |
|---|---|---|
| `/json/new` 建的是后台标签 | 采集时看到的是一片空白 | 建完 `bring_to_front()`，并关掉启动时的 `about:blank` |
| `--user-data-dir` 用相对路径 | 「调试端口没响应」，浏览器起不来 | 必须 `os.path.abspath` |
| 窗口位置只设 `windowState` | 窗口恢复到屏幕外，人看不见 | 显式设 `left/top/width/height`，且**分两次** `setWindowBounds` |

还有一条：退出时用 `Browser.close`（而不是 kill 进程），否则**登录态不落盘**，下次还要重登。

### 1.5 知乎：直连 HTTP 一定 403

`urllib` 直接抓知乎正文 100% 403（连 Cookie 带齐也一样）。
唯一稳的办法是**在浏览器页面上下文里** `fetch(url, {credentials:'include'})`，
即用 `browser_cdp.eval_js(..., awaitPromise=True)` 在页面里发请求。
专栏文章还要走另一条：页面 `goto` 后读 `.Post-RichText`（专栏接口会 404）。

### 1.6 GitHub 不适合做「观点检索」源

实测搜 `monolith` 返回的是：33KB 内核模块化设计草稿、webpack 构建优化、图片下载进度条。
GitHub 的内容结构是「缺陷报告 / 设计草稿」，不是观点文章。
→ **GitHub 只用于信息采集与定向查询，反仓库侧不用它检索观点。**
观点检索主力是 V2EX（经第三方服务 sov2ex，V2EX 官方 API 不提供搜索），掘金补充，HN 可选。

### 1.7 评测有噪声，别把单次结果当定论

字节级相同的 prompt 连跑两次，失败的条目会变 —— **服务端缓存会伪装成确定性**。
所以：报数字时给的是多次平均；不要为了「这次跑出 100%」去反复重跑挑结果。

## 2. 产品局限（主动交代）

| 局限 | 实情 | 我们怎么处理 |
|---|---|---|
| **议题是封闭的** | 只有 16 个二元议题，都是技术圈的经典争论 | 议题表可扩（三处一起改）；现在不假装能覆盖一切 |
| **中文观点检索可用率约 1/4** | 4 条候选里约 1 条能用 | 所以更看重「少而准」：宁可 0 条，不出错条 |
| **有的议题天生检索不到** | 16 个议题里 3 个好、9 个弱、2 个失效 | 失效的（梗类）直接进 `NO_RETRIEVAL`，不装 |
| **单条耗时长** | 一条 50–100 秒，10 条约 15 分钟 | 前端必须做进度条；演示先跑 GitHub |
| **抖音/微博判不出立场** | 视频详情页正文太短 | 明确标「只归档」，不做半吊子判断 |
| **第三档（AI 自编）默认关** | 它能保证「一定有反信息」，但没有真实出处 | 默认关；开了打 `synthesized:true` 并视觉区分；答辩主动说 |
| **论证质量分未上线** | `argument_score` 恒为 `null` | **界面不要把它显示成 0 分**，显示「未评分」 |
| **没有用户体系/多用户** | 单机单用户，数据在本地 JSONL | 本期规模不需要；上库不改字段 |

## 4. 不要做的五件事

1. **不要放松闸门去凑 ★ 数量。** 反库一旦混进「有点不一样」，整个产品就退化成杠精池。
2. **不要改 `SYSTEM_PROMPT` 来修个案。** 个案用 `TOPIC_GUARD` / 议题表处理；改 prompt 会让 90.2% 的基线作废。
3. **不要编 URL、不要编正文。** 抓不到就如实报失败（`vault_fetch` 已有明确失败路径）。这是全系统的信誉地基。
4. **不要把 `synthesized` 默认打开。** 它可以救场，但它是唯一「没有出处」的东西；默认开等于悄悄骗用户。
5. **不要收密码。** 不做「拿账号密码 POST 登录表单」：三家平台都有验证码与设备校验，脚本必被拦；
   密码落盘是这类应用里最贵的一类漏洞。正确做法是弹窗让人自己登，程序只复用登录态目录。

## 5. 答辩可以直接用的话

- **「你们怎么防幻觉？」**
  LLM 只回答两个问题：这条属于哪个议题、它站哪边。**答案一律来自真实检索**，
  每条反信息都有 `url` + `evidence_span`（原文里支撑它站这边的那一段），能一键回现场。

- **「为什么不干脆让模型生成反面观点？」**
  能做，而且我们留了位置（第三档 `synthesized`）。但它**默认关闭**，因为生成的文字没有出处，
  而「有出处」正是这个产品唯一的价值。开着它，用户没法验证我们没在编。

- **「如何避免变成抬杠？」**
  六道闸门（对立性表述、对立度 ≥0.7、观点性复检、议题守卫、自指排除、议题覆盖度），
  外加排序里对立度只占 40%、论证质量同样占 40%。**用评分机制强制「要讲理」。**

- **「覆盖率不高怎么办？」**
  实测中文观点检索可用率约 1/4，我们选择**少而准**：宁可这一条显示「暂未找到」，
  也不塞一条错的进去。补源比换算法收益大，这是下一步。

- **「这个开关是真的吗？」**
  关掉之后 `run_vault` 会**直接拒绝生成**，不是 UI 遮罩。现场可以演示：关 → 重采 → 反库不再增加。
