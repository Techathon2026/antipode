## 步骤 1:装 Python

**去哪里:** 浏览器打开 <https://www.python.org/downloads/>

**用什么:** 下载 Python 3.11 或更高版本(Windows 选 `Windows installer (64-bit)`)

**⚠️ 安装时最重要的一个勾选:**  
安装第一屏底部有个 **"Add python.exe to PATH"** —— **必须勾上**。不勾的话后面命令行找不到 python。

**验收标准:** 打开 PowerShell,输入:

```powershell
python --version
```

能打出 `Python 3.1x.x` 就算成功。

> **如果提示"无法识别 python":** 说明没勾 PATH。重新运行安装程序选 "Modify" 补勾,或者直接用本机已有的:  
> `C:\Users\1\.workbuddy\binaries\python\versions\3.13.12\python.exe`

## 步骤 4:配置密钥

**在哪里做:** 在 `code` 目录里,把模板复制成正式文件:

```powershell
Copy-Item .env.example .env
```

**然后用记事本打开 `.env`,填入你的密钥:**

```powershell
notepad .env
```

**改完应该长这样(以 DeepSeek 为例):**

```
OPENAI_API_KEY=sk-你刚才复制的那串密钥
OPENAI_BASE_URL=https://api.deepseek.com/v1
STANCE_MODEL=deepseek-chat
```

**⚠️ 三个注意点:**

1. 只改 `OPENAI_API_KEY=` 后面的内容,**不要加引号、不要留空格**
2. 如果你选的是通义/智谱/OpenAI,**把另外两个变量也换成对应方案**(模板里都有,注释掉的方案 B/C/D 直接启用即可)
3. `.env` 里是真实密钥,**不要提交到 git**(建议加进 `.gitignore`)

**验收标准:** `.env` 文件存在,里面 `OPENAI_API_KEY` 后面是你真实的密钥。

## 步骤 6:跑一条真实抽取(第一次花钱)

**在哪里做:** PowerShell,`code` 目录下:

```powershell
python stance_extractor.py --text "我们去年上了微服务,结果光是链路追踪就搭了三个月,一个下单请求要跨七个服务,排障时间翻了三倍。"
```

**期望输出:**

```
抽到 1 条立场

议题      microservices_vs_monolith
立场      con (strong)  置信度 0.85
处理      accept
证据      一个下单请求要跨七个服务,排障时间翻了三倍
理由      未直接表态,但罗列的全是负面后果,隐含反对
----------------------------------------
```

**⚠️ 注意这句话的字面意思——它一个字都没说"我反对微服务"**,但期望模型判出 `con`。**这就是"隐含立场",也是这一环最核心的能力。**

**验收标准:** 输出了 `polarity: con` 和一段真实存在的原文证据。

> **如果输出"未抽到任何立场":** 可能是证据校验没通过(模型改写/编造了证据)。换个说法再试,或看步骤 8。

## 步骤 7:跑评测,看准确率

**在哪里做:** PowerShell,`code` 目录下:

```powershell
python stance_extractor.py --eval gold_set.jsonl
```

**期望输出:**

```
评测结果
--------------------------------
样本数           18
立场准确率       88.9%   (目标 >80%)
议题对齐准确率   94.4%   (目标 >90%)
证据校验通过率   100.0%   (目标 >95%, 低于则模型在编证据)
```

**⚠️ 三个指标里,第二个(证据校验通过率)最要盯。**

| 指标          | 含义        | 低了怎么办                          |
| ----------- | --------- | ------------------------------ |
| 立场准确率       | 判对了几成     | 加 few-shot 示例                  |
| 议题对齐准确率     | 议题选对了几成   | 议题清单描述写清楚点                     |
| **证据校验通过率** | 证据真的在原文里吗 | **低于 95% = 模型在编 → 必须改 prompt** |

**验收标准:** 三个指标都达标。**达标就说明 3.3 这一环通了。**

## 步骤 8:调 prompt(如果指标不达标)

**在哪里做:** 用记事本或 VS Code 打开 `code\stance_extractor.py`

**要改的两个地方:**

### 改① 议题清单(找不到议题 / 议题选错)

文件里搜 `ISSUE_TAXONOMY`,把议题改成你自己项目要用的。

### 改② Few-shot 示例(立场判错)

文件里搜 `FEW_SHOT`,里面给了 5 个示例,分别对应:

1. 直接支持
2. **隐含反对** ← 最重要
3. 讽刺反话
4. 仅转述(undetermined)
5. 中立

**把你的真实语料里判错的例子,加工成示例加进去。** 加 3-5 个,准确率通常会明显上升。

**改完记得:**

```powershell
python stance_extractor.py --eval gold_set.jsonl
```

**⚠️ 改完 prompt 后,把 `stance_extractor.py` 里的 `TAXONOMY_VERSION` 加一**(`"v1"` → `"v2"`),否则缓存会返回旧结果。

## 步骤 9(下一步):接到产品里

这一步做完,你的立场抽取就是一个**可调用的函数**:

```python
from stance_extractor import extract_long, gate

stances = extract_long(某条信息的内容)

for s in stances:
    if s.gate == "accept":          # 高置信, 全流程可用
        存入仓库(s)
        送去建反信息(s)
    elif s.gate == "review":        # 中置信, 只进仓库
        存入仓库(s)
    # reject 的直接丢弃
```

**注意 `gate` 的用法:反仓库只收 `accept` 的,仓库可以收 `accept` + `review`。**

## 常见报错速查

| 报错                                              | 原因              | 怎么办                               |
| ----------------------------------------------- | --------------- | --------------------------------- |
| `ModuleNotFoundError: No module named 'openai'` | 没装依赖            | 回步骤 3                             |
| `KeyError: 'OPENAI_API_KEY'`                    | 没配密钥 / 文件没保存    | 回步骤 4,确认文件名是 `.env` 不是 `.env.txt` |
| `401 Unauthorized`                              | 密钥错了            | 检查密钥有没有多余空格、引号                    |
| 连接超时                                            | base_url 错了     | 检查 `.env` 里的 `OPENAI_BASE_URL`    |
| `未抽到任何立场`                                       | 议题不匹配 or 证据校验没过 | 换文本再试;查步骤 8                       |
| 全部落到 `reject`                                   | 置信度普遍偏低         | 把阈值从 0.6/0.8 调低一点试试               |
