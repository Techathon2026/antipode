# Antipode · 对跖点 —— 反仓库侧交付包

> 这是「反仓库」这一侧**全部可运行成果**，为接手的人 / agent 准备。
> **这个文件夹 `first/` 本身就是交付物** —— 没有副本、没有分支版本，改这里就是改全部。
>
> **自包含**：整个文件夹拷到任何一台装了 Python 3.9+ 的机器上，
> `python code/selftest.py` 就能跑出 42 项全绿 —— 不联网、不花钱、不需要密钥。
> 需要真实采集时才要 `code/.env`（模板已给）和网络。
>
> 🤖 **给自动编码 agent（Codex / Claude Code 等）**：先读 [`AGENTS.md`](AGENTS.md) —— 那里是可直接执行的接手指令。

## 0. 这个项目是什么（三句话）

1. 它把用户关注的信息收进一个**仓库**，再自动建一个**反仓库** —— 存放他**没看见、但值得看见**的信息（同议题的对立面 + 别人的反驳证据）。
2. 入口不是「一堆链接」，而是**一个主页网址 + 账号**：GitHub / 知乎 / 抖音 / 微博。登录由用户自己在弹出的窗口里完成，程序只读，**不接触密码**。
3. 每条反信息都**必须带真实 URL 和原文证据**：LLM 只负责「提出问题」（这条属于哪个议题、它站哪边），答案一律来自真实检索。这条是硬规矩，不允许为了演示效果放松。

**已跑通的链路**（都有实测数字，见 `04_坑与限制.md`）：

```
采集（按平台） → 去广告/垃圾 → 省流 → 判立场 → [可选] 找反面 → 建库 / 反库 → HTTP 接口给界面
```

## 5. 三条铁律（改代码前必须知道）

1. **LLM 只负责提问，答案必须来自真实检索。** 反库每条都要有真实 URL；抓不到就报失败，**绝不编造正文或链接**。
2. **对立面是符号运算**：`takes_side == opposite(原条目.supports)`。没有「大致相反」，也没有「有点不一样」。
3. **默认关闭一切可能说谎的东西**：第三档 `synthesized`（AI 自编，无真实 URL）默认关，开了必须打标并做视觉区分。

## 6. 三件不做的事（写死在代码里，别改回去）

1. **不收密码。** 不做「拿账号密码 POST 登录表单」。GitHub 用只读 token；其它平台弹窗让人自己登，程序只复用本机登录态目录。
2. **不把登录态返回给前端。** 接口里没有 token / cookie 字段（`_public()` 主动剥离）。
3. **不默认监听外网。** `127.0.0.1` 起，这是本机应用的后端，不是云服务。

---

## 7. 已知边界（是设计，不是 bug）

- **GitHub 只做信息收集，不做反推荐**：代码仓库没有「观点立场」。你会在界面上看到开关是灰的、理由写在提示里。
- **抖音/微博多数只归档**：视频和短文本判不出立场，工具不会硬判。
- **知乎热榜 ≠ 可反推荐**：热榜是综合时事，与我们那 16 个技术议题一条都不沾边（实测 10/10 被拦）。要反推荐必须**按议题或关键词采集**。
- **反推荐不是每条都有产出**：一条信息可能「适合反推荐但这次没找到合格的对面」。这不是故障，界面要如实说「暂未找到」。

## 8. 与仓库其它部分的关系

- 本文件夹 = **唯一工作副本**。仓库里没有第二份 `code/`、`data/`（旧的重复副本已清掉），所以不存在「改哪一份」的问题。
- `second/` 是队友那一侧（兴趣筛选 / 分类模型），与本文件夹**无代码耦合**，只通过 [`INTEGRATION.md`](INTEGRATION.md) 对齐字段。
- 仓库根的 `README.md` 是给评委看的项目总览；**做开发只看这个文件夹**。
