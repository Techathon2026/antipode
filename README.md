# Antipode · 对跖点

> TECHATHON 2026 参赛项目 · 暂定名，可随时更换
>
> 仓库地址：<https://github.com/Techathon2026/antipode>
> （个人镜像：<https://github.com/ciqiongovo/antipode>）

**一句话：** 它帮你把"你关注的信息"收进一个仓库，再自动为你建一个**反仓库** —— 存放那些你**没看见、但值得看见**的信息。

---

## 1. 它解决什么问题

今天的信息工具都在做同一件事：**把你想看的推给你。**

结果是每个人的信息视野越用越窄 —— 你关注微服务，它就只给你微服务；你相信 TDD，它就只给你 TDD 的成功案例。**没有人负责告诉你："这件事还有另一面。"**

Antipode 做了两件事，而且是对称的：

| 仓库（Vault） | 反仓库（Antipode） |
|---|---|
| 你说要什么，它去各个源里筛 | 它专门去找**与这些信息相对立/互补**的内容 |
| 让你**读得完** | 让你**看得见盲区** |
| 排序：契合度 × 时间 | 排序：对立度 × 论证质量 |

---

## 2. 核心概念：`相反` 不是一种东西，是三种

> 这是整个产品的设计地基。不区分的话，反仓库必然退化成"杠精池"。

| 类型 | 定义 | 例子 | MVP |
|---|---|---|---|
| **A 观点对立** | 同议题、反立场 | 你信微服务 → 推"单体更好" | ✅ 先做，用来跑通链路 |
| **B 反向证据** | 反驳你结论的具体事实 | 你信"微服务=高可用" → 推"某公司因微服务宕机 12 小时" | ⭐ 演示亮点 |
| **C 视野缺失** | 你完全没覆盖的相邻议题 | 你只看微服务 → 推 Serverless | ⭐ 架构留位，人工预置 1 个例子 |

数据模型里用 `counter_type` 字段**一次性把三个位置留出来**，否则后期改不动。

## 3. 它是怎么工作的

```
用户一句话  →  授权信息源  →  双仓库
   │
   ├─ 采集层：GitHub / 邮件(IMAP) / RSS … 全部转成同一个文档 Schema
   │
   ├─ 智能层：① 主题+立场抽取  ② 生成对立假设  ③ 检索真实来源  ④ 验证打分
   │
   └─ 仓库 ← 契合度排序       反仓库 ← 对立度 × 论证质量 排序
                                  └─ 每条都带「回现场」深链接
```

**贯穿全流程的一条铁律：**

> **LLM 只负责「提出问题」，绝不负责「提供答案」。答案必须来自真实检索。**

这是防幻觉唯一可靠的方式，也是答辩时最该强调的技术原则。

**防杠精化四道闸门 + 一道议题守卫：**
1. 必须有**论证结构**（没有"前提 → 结论"的一律丢弃）
2. 必须有**可验证出处**（没有 URL 的一律丢弃）—— 且证据必须是候选原文的**真实子串**
3. 对立度必须达阈值
4. 观点性复检（教程 / 源码解析不是"反面观点"）
5. **议题守卫**：字面命中但讨论的不是这场争论的，直接拦
   （「过度依赖辅助驾驶」不是「反对 AI 编程助手」，「自建 CDN」不是「自建 vs 上云」）

> 反仓库排序里，`对立度` 只占 40%，`论证质量` 同样占 40%。
> 用评分机制强制"不要抬杠，要讲理"。

## 5. 快速开始

```bash
git clone https://github.com/Techathon2026/antipode.git
cd antipode

# 依赖（核心链路只用标准库，这一步只是为了 .env 解析与可选 SDK）
python -m pip install -r code/requirements.txt

# 配置密钥（真实密钥只写在 .env 里，绝不要提交）
cp code/.env.example code/.env

# 自检（不花钱，不调用 API）
python code/stance_extractor.py --selftest
python code/antipode_engine.py --selftest        # 反引擎离线自检

# 一个库 → 一批反库条目（先 --dry-run 看会怎么处理）
python code/run_vault.py --vault data/vault_demo.json --dry-run
python code/run_vault.py --vault data/vault_demo.json

# 只有链接也能跑（条目里只写 {"url": "..."}）
python code/run_vault.py --vault data/vault_url_only.json

# 起一个 HTTP 接口给前端 / 队友调
python code/server.py --port 8787
curl -s -X POST http://127.0.0.1:8787/antipode \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://blog.csdn.net/fudaihb/article/details/136061101"}'

# 重新生成答辩看板（跑完实验后执行，数字自动更新）
python code/make_defense_page.py

# 单条跑 + 看漏斗
python code/antipode_engine.py --json code/vault_item.example.json --origin v2ex
```

详细步骤见 [`docs/快速上手_操作手册.md`](docs/快速上手_操作手册.md)，
流水线的机制与实测数字见 [`docs/反仓库流水线_模块说明.md`](docs/反仓库流水线_模块说明.md)。

## 6. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 接入层 | GitHub REST API（PAT）/ IMAP | **不用 OAuth**，黑客松现场最容易翻车 |
| 数据层 | Postgres + pgvector | 文档元数据 + 向量 |
| 智能层 | DeepSeek / GLM / GPT（OpenAI 兼容接口） | 结构化输出 + LLM as Judge |
| 检索 | 向量 + BM25 混合（RRF 融合） | 单用向量会漏精确术语 |
| 编排 | 异步任务队列 | 采集 + 多次 LLM 调用 > 30s，同步请求必然超时 |
| 交互层 | Next.js | 结果卡片 + 「回现场」深链接 + 授权面板 |

## 7. 第三方资源说明

> 赛事提交清单要求：第三方代码、模型、数据集等需注明来源。

| 资源 | 来源 | 用途 | 授权/说明 |
|---|---|---|---|
| DeepSeek API | 比赛方提供（TECHATHON 2026 现场资源） | 立场抽取 / 摘要 / LLM as Judge | 现场领取，接口地址以现场通知为准 |
| 智谱 GLM-4-flash | 智谱开放平台 | 立场抽取 / 议题定位 / 摘要（当前实测所用） | **官方免费档（价格 0）**，需自备 API Key |
| 影眸 Hyper3D | 比赛方提供（兑换码，需上科大邮箱注册） | 3D 信息星图展示 | 会员兑换码，见现场资源页 |
| GitHub REST API | GitHub 官方 | 信息源采集；定向检索 | 个人访问令牌（PAT）。⚠️ 实测不适合做观点检索源，详见下方说明 |
| **Hacker News Algolia API** | Algolia 为 Y Combinator 的 HN 提供 | 英文对立内容检索 | 公开免费接口，**无需鉴权** |
| **V2EX 检索（经 sov2ex）** | **第三方搜索服务** | 中文对立内容检索（主力源） | ⚠️ **V2EX 官方 API 不提供搜索接口**，故使用第三方服务 sov2ex。特此注明 |
| **掘金开放搜索接口** | 掘金官方 | 中文对立内容检索（补充源） | 公开接口；实测召回不稳定，仅作补充 |
| Postgres + pgvector | 开源 | 数据与向量存储 | PostgreSQL License |
| OpenAI Python SDK | 开源 | 调用各兼容接口 | Apache-2.0 |
| 议题清单 / 检索词表 / 评测集 | **本项目自建** | 立场对齐、检索、评测 | 人工编写并经实测调优 |

> **关于三个检索源的取舍**（完整实测见 [`docs/反仓库检索_实测记录.md`](docs/反仓库检索_实测记录.md)）：
> GitHub 的内容结构是"缺陷报告 / 设计草稿"，不是观点文章 —— 实测搜 `monolith` 返回的是
> 33KB 内核模块化草稿、webpack 构建优化、图片下载进度条。因此反仓库侧**不用 GitHub 做观点检索**，
> GitHub 仅用于信息采集与定向查询。
> 观点检索以 **V2EX（经第三方服务 sov2ex）为主力**，Hacker News 补英文，掘金作补充。

## 9. 路线图

- **P0（第 1–6 小时）** 硬编码议题 → 一张仓库卡片 + 一张反卡片 → 点击跳转。**这条链路不通，后面全是空中楼阁。**
- **P1** GitHub 单源端到端打通 + 立场抽取接真实模型
- **P2** 反仓库 A 类（观点对立）自动化
- **P3** B 类（反向证据）+ 论证质量打分
- **P4** 邮件源接入（IMAP）+ 3D 星图
