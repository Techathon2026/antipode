## 步骤 2:拿到模型 API 密钥

**你需要两样东西:密钥(key)+ 接口地址(base_url)。缺一不可。**

### 方案 0:比赛方提供的 DeepSeek(已到手,但缺接口地址)

现场资源页给了:

```

model: deepseek-pro
```

**但没有给 base_url。** 实测这个 key 直接请求 DeepSeek 官方接口返回 **401**,
说明它是**比赛方自建网关**的密钥。

**要做的:** 问现场工作人员 / 赛事群要接口地址,拿到后填进 `.env` 即可。

> ⚠️ **不要为了等这个地址卡住开发。** 先用下面任意一个方案把流水线跑通,
> 地址拿到了改一行配置就能切过去。

### 方案 A:智谱 GLM ★现在就能跑,推荐

- **去哪里:** <https://open.bigmodel.cn>
- **怎么点:** 注册登录 → 控制台 →「API Keys」→ 新建
- **优势:** `glm-4-flash` 有**免费额度**,不用充值
- **配置值:**
  ```
  OPENAI_BASE_URL=https://open.bigmodel.cn/api/paas/v4

  ```

### 方案 B:DeepSeek 官方

- **去哪里:** <https://platform.deepseek.com>
- **怎么点:** 注册 → 左侧「API keys」→「创建 API key」
- **充值:** 先充 10 块够跑很久
- **配置值:**
  ```
  OPENAI_BASE_URL=https://api.deepseek.com
  STANCE_MODEL=deepseek-flash
  ```
  > 注意:官方 model 名是 `deepseek-flash`,不是 `deepseek-pro`

### 方案 C:阿里云百炼(通义千问)

- **去哪里:** <https://bailian.console.aliyun.com>
- **怎么点:** 登录 → 右上角「API-KEY」→「创建我的 API-KEY」
- **配置值:** `https://dashscope.aliyuncs.com/compatible-mode/v1` + `qwen-plus`

### 方案 D:OpenAI 官方

- **去哪里:** <https://platform.openai.com/api-keys>
- **注意:** 需要海外支付方式

**⚠️ 密钥通常只显示一次,一定要当场复制存好。**

**验收标准:** 手里有一串**密钥** + 一个 `https://` 开头的**接口地址**。

## 步骤 6:跑一条真实抽取(第一次花钱)

**在哪里做:** PowerShell,`code` 目录下:

```powershell
python stance_extractor.py --text "我们去年上了微服务,结果光是链路追踪就搭了三个月,一个下单请求要跨七个服务,排障时间翻了三倍。"
```

**期望输出:**

```
抽到 1 条立场

议题      microservices_vs_monolith
支持      单体  [side=b]  强度 strong  置信度 0.85
处理      accept   → 反仓库对立面: 微服务
证据      一个下单请求要跨七个服务,排障时间翻了三倍
理由      未直接表态,但罗列的全是负面后果,隐含反对
----------------------------------------------
```

**⚠️ 注意这句话的字面意思——它一个字都没说"我反对微服务"**,但期望模型判出 `supports = 单体`。**这就是"隐含立场",也是这一环最核心的能力。**

**注意最后那行 `→ 反仓库对立面: 微服务`** —— 这就是反仓库要去找的那一方,整条链路的关键交接点。

**验收标准:** 输出了 `supports: 单体`(即 `side=b`)和一段真实存在的原文证据。

> **如果输出"未抽到任何立场":** 可能是证据校验没通过(模型改写/编造了证据)。换个说法再试,或看步骤 8。

## 步骤 7:跑评测,看准确率

**在哪里做:** PowerShell,`code` 目录下:

```powershell
python stance_extractor.py --eval gold_set.jsonl
```

**期望输出(这是实测跑出来的真实数字,智谱 `glm-4-flash-250414`):**

```
评测结果
--------------------------------------------------
样本数              41
模型调用次数        41
立场准确率(4分类)   90.2%   (目标 > 80%)
  ├ 有效立场准确率   94.3%   (期望 a/b 的 35 条, 决定仓库/反仓库放得对不对)
  └ 排除判定准确率   100.0%   (期望 neutral/undetermined 的 6 条, 决定该丢的有没有丢掉)
议题对齐准确率      97.6%   (目标 > 90%)
证据校验通过率      100.0%   (目标 > 95%, 低于说明模型在编证据)
自创议题率          0.0%   (目标 0%)
```

**⚠️ 六个指标里,「证据校验通过率」最要盯。**

| 指标              | 含义                | 低了怎么办                          |
| --------------- | ----------------- | ------------------------------ |
| 立场准确率(4分类)     | 严格判对了几成           | ⚠️ 先别急着改,见下面的噪声警告              |
| ├ 有效立场准确率      | **站对边了几成** ← 最影响产品 | 加 few-shot 示例                  |
| └ 排除判定准确率      | 该丢的有没有丢掉          | 一般不会低,低了说明模型过度站队               |
| 议题对齐准确率         | 议题选对了几成           | 议题清单描述写清楚点                     |
| **证据校验通过率**     | 证据真的在原文里吗         | **低于 95% = 模型在编 → 必须改 prompt** |
| 自创议题率           | 模型发明清单外议题的比例      | 不为 0 说明清单约束没生效,检查 prompt       |

> ⚠️⚠️ **最重要的一条:不要只跑一轮就下结论。**
> 实测**同一个 prompt 重跑,失败条目会变**(约 ±1~2 条 / ±3~5%)。
> 单轮的分数差 2~3 个百分点,很可能只是噪声。
>
> 而且**不要连续紧挨着重跑** —— 服务端会命中缓存,给你"三次完全一致"的假象。
> 正确做法:隔几分钟跑一轮,共跑 3 轮,看**失败集合是否稳定**(每轮都错 = 真弱点;时对时错 = 噪声)。
> 详见 `docs/立场抽取_实施指南.md` 第 8 节。

> 评测跑完还会打印**未通过样本清单**(期望值 / 实得值 / 原文片段)。
>
> 想先不花钱看流水线长什么样,加 `--mock` —— 那是离线假模型,数字无参考价值。

**验收标准:** 有效立场准确率、排除判定准确率、证据校验通过率、议题对齐准确率四项达标
(判据:`docs/立场抽取_实施指南.md` 第 9 节的"门禁阈值建议")。**达标就说明 3.3 这一环通了。**

## 步骤 8:调 prompt(如果指标不达标)

**在哪里做:** 用记事本或 VS Code 打开 `code\stance_extractor.py`

**要改的两个地方:**

### 改① 议题清单(找不到议题 / 议题选错)

文件里搜 `ISSUE_TAXONOMY`,把议题改成你自己项目要用的。

### 改② Few-shot 示例(立场判错)

文件里搜 `FEW_SHOT`,里面给了 5 个示例,分别对应:

1. 直接支持
2. **隐含反对** ← 最重要
3. 讽刺反话
4. 仅转述(undetermined)
5. 中立

**把你的真实语料里判错的例子,加工成示例加进去。** 加 3-5 个,准确率通常会明显上升。

**改完记得:**

```powershell
python stance_extractor.py --eval gold_set.jsonl
```

**⚠️ 改完 prompt 后,把 `stance_extractor.py` 里的 `TAXONOMY_VERSION` 加一**(`"v1"` → `"v2"`),否则缓存会返回旧结果。

## 步骤 9(下一步):接到产品里

这一步做完,你的立场抽取就是一个**可调用的函数**:

```python
from stance_extractor import extract_long, gate

stances = extract_long(某条信息的内容)

for s in stances:
    if s.gate == "accept":          # 高置信, 全流程可用
        存入仓库(s)
        送去建反信息(s)
    elif s.gate == "review":        # 中置信, 只进仓库
        存入仓库(s)
    # reject 的直接丢弃
```

**注意 `gate` 的用法:反仓库只收 `accept` 的,仓库可以收 `accept` + `review`。**

## 常见报错速查

| 报错                                              | 原因              | 怎么办                               |
| ----------------------------------------------- | --------------- | --------------------------------- |
| `ModuleNotFoundError: No module named 'openai'` | 没装依赖            | 回步骤 3                             |
| `KeyError: 'OPENAI_API_KEY'`                    | 没配密钥 / 文件没保存    | 回步骤 4,确认文件名是 `.env` 不是 `.env.txt` |
| `401 Unauthorized`                              | 密钥错了            | 检查密钥有没有多余空格、引号                    |
| 连接超时                                            | base_url 错了     | 检查 `.env` 里的 `OPENAI_BASE_URL`    |
| `未抽到任何立场`                                       | 议题不匹配 or 证据校验没过 | 换文本再试;查步骤 8                       |
| 全部落到 `reject`                                   | 置信度普遍偏低         | 把阈值从 0.6/0.8 调低一点试试               |
