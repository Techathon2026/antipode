# 03 · 运行与验证

> 目标：从零到「看到第一条反信息」不超过 10 分钟；以及出问题时知道该看哪。

---

## 1. 环境

- **Python 3.9+**，核心链路**零第三方依赖**（只用到标准库）
- 只有 `.env` 解析与可选 SDK 需要 `code/requirements.txt` 里那几个包（不装也能跑离线部分）
- 系统自带浏览器（Chrome / Edge）—— 采集走 CDP 驱动它，不额外装驱动

```bash
cd HANDOFF
cp code/.env.example code/.env     # 然后填密钥
python -m pip install -r code/requirements.txt   # 可选
```

`.env` 里只有三样关键：

```ini
OPENAI_API_KEY=...                  # 任何 OpenAI 兼容接口的密钥
OPENAI_BASE_URL=https://open.bigmodel.cn/api/paas/v4
STANCE_MODEL=glm-4-flash-250414     # 官方免费档，价格 0，实测够用
```

> 模型是**模型无关**的：换 DeepSeek / 通义 / GPT 只改这三个环境变量，代码不动。
> `.env.example` 里已经按四家写好了四组注释，挑一组取消注释即可。

其它可选环境变量（排查时用得上）：

| 变量 | 作用 |
|---|---|
| `ANTIPODE_NO_PROXY=1` | 忽略系统代理（公司网络下采集卡住时试它） |
| `ANTIPODE_DEBUG=1` | 打印检索/闸门的中间过程 |
| `ANTIPODE_BACKEND` | 模型后端，默认 `openai_compat` |

## 3. 三条采集链路（各自都能单跑）

### 3.1 GitHub 新项目（不用登录，最快，15 秒）

```bash
python code/collect_github.py --days 7 --limit 10
python code/collect_github.py --days 30 --lang python --min-stars 50 --token <只读PAT>
```
产出：`data/vault_github-new-<时间>.json` + `.items.jsonl` + `data/digest_github-new-<时间>.md`（给人看的日报）

> 这条线**只做信息收集**：仓库没有「对立面」，`antipode_eligible` 全为 false，理由写在条目里。

### 3.2 知乎（必须登录一次；这条线带反推荐）

```bash
python code/collect_zhihu.py --limit 10                        # 默认热榜（只做收集）
python code/collect_zhihu.py --scope feed                      # 首页推荐流（只做收集）
python code/collect_zhihu.py --issue microservices_vs_monolith  # ← 要反推荐用这个
python code/collect_zhihu.py --query "远程办公" --antipode       # ← 或这个
```

流程：过滤广告/盐选小说/种草软文/空壳（丢弃记录进 `*.junk.jsonl`，带原因）
→ 浏览器会话内取正文（**HTTP 直连知乎稳定 403**）
→ 判议题与立场 → 写省流 → 需要才跑反推荐。

常用参数：`--limit` `--scroll` `--wait 300`（等登录秒数）`--profile <目录>` `--no-model`（只测采集）`--keep-open`（采集完不关窗口）。

### 3.3 账号主页（抖音 / 微博 / GitHub 账号）

```bash
# GitHub 账号（走官方 API，最稳）
python code/collect_account.py --url https://github.com/<账号> --token <PAT> \
       --scope starred --vault-id client-gh --topic "他 star 过的"

# 抖音 / 微博：必须人自己登录
python code/collect_account.py --url https://www.douyin.com/user/<id> --browser \
       --vault-id client-dy --topic "他的作品" --limit 20
```

三种认证：`--token`（最稳）/ `--cookie`（串或文件）/ `--browser`（弹窗，人过验证码）。
`--username/--password` **只做预填**（只在内存里，不落盘不打印），登录动作仍由人点。

### 3.4 只有一堆链接时

```bash
python code/build_vault.py --urls links.txt --vault-id client-a --topic "前端选型"
```

## 4. 反推荐（一个库 → 一批反库条目）

```bash
python code/run_vault.py --vault data/vault_zhihu-1017T2051.json --dry-run   # 先看会处理哪些
python code/run_vault.py --vault data/vault_zhihu-1017T2051.json             # 真跑
python code/run_vault.py --vault data/vault_url_only.json                    # 条目里只写 {"url":...} 也能跑
```

产出三个文件：`antipode_<id>.jsonl`（反库）、`.stats.json`（漏斗报告）、原库文件回填统计。

**耗时预期**：单条约 50–100 秒（检索 + 模型判立场 + 证据校验），10 条约 15 分钟。
`--limit N` 只跑前 N 条，`--no-resume` 重跑已经跑过的条目。

## 7. 常见故障（都实际踩过）

| 现象 | 原因 | 解法 |
|---|---|---|
| 知乎正文全部 403 | 知乎拒绝 urllib 直连 | 必须在**页面会话内** `fetch(credentials:'include')`；代码已这么做，别改回直连 |
| 采集时弹出空白页 | CDP 新建的是**后台标签**，显示的是启动时的 `about:blank` | 代码里 `bring_to_front()` + 关掉空白页；自己写 CDP 时要注意 |
| 「调试端口没响应」 | `--user-data-dir` 用了相对路径，与默认 profile 冲突 | 必须转绝对路径（代码已做） |
| 浏览器窗口出现在屏幕外 | 只设 `windowState` 不够 | 显式设 `left/top/width/height`，且**分两次** `setWindowBounds` |
| CSDN 间歇 521 | 站点限流 | 已有退避重试；抓不到就报失败，**不要编正文** |
| 双击 `.bat` 没反应 | cmd 层读完 stdin 就退出 / 文件被读坏 | Python 不读键盘（选择在 cmd 的 `set /p`）；`.bat` 必须 **CRLF + 纯 ASCII**，第一行 `chcp 65001` |
| 中文乱码 | Windows 控制台编码 | 各脚本入口已 `sys.stdout.reconfigure(encoding='utf-8')` |
| `platforms.json` 被提交进 git | 它是运行时状态 | `.gitignore` 已排除 `first/data/platforms.json`，**新目录记得同步规则** |
| 端口被占用 | 上次没杀干净 | `netstat -ano | findstr 8790` → `taskkill /PID <pid> /F` |
