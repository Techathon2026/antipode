## 来源维度

用户提出的“书院活动、学院活动”应保留可检索性。建议用独立来源维度表达，避免和内容类型互相冲突：

- source_scope：书院、学院、校级部门、课程平台、校外机构、个人、待确认。
- source_unit：从发件人可确认的单位或平台，例如科道书院、信息学院、图书馆、Gradescope；不能确认时留空。
- 来源是发送/转发单位，不自动等于活动主办单位。不得根据发件人推断未知主办方。
- 可以组合筛选“书院来源 + 文体活动”“学院来源 + 学术讲座”。若用户坚持将书院活动和学院活动直接作为母标签，需要先确定与内容类型发生冲突时的优先级。

## 交叉与不确定性规则（待确认）

1. 优先按邮件主要目的分类，不按“通知”“讲座”“招募”字样机械分类。
2. 招聘宣讲 → C07；升学宣讲 → C06；学术讲座 → C04；工具操作培训 → C05。
3. 赛事志愿者招募 → C12；参赛报名 → C09（科技类）或 C10（文体类）。
4. 学生社团/校队招新 → C11；校内助教助管招聘 → C08；企业校园大使 → C07。
5. 课程作业回执与课堂平台入课通知 → C01；课程平台密码重置和验证码 → C17。
6. 后勤服务调整 → C16；信息平台维护 → C17；消防/台风风险提醒 → C15。
7. “Re:”“已接受”“【草稿】”作为邮件形式或状态记录，不直接决定内容类型；已发送邮件也不能当作无关邮件。
8. 明确课程要求（如形策修读或心理必修环节）优先 C01，可加 C13/C14 次要类型；只写“讲座预告”且课程属性不明时标待核查。
9. 内容不清时，不强行贴确定类型。category 可留空，review_status 标“需正文确认”，并记录候选类型和理由；需要时 needs_body=1。
10. 其他 OTHER 是内容类型；“需正文确认”是复核状态，二者分别记录。
