# 账号采集 · 客户给一个网址和账号，怎么把他的内容读出来

> 现状：客户不再给一堆文章链接，而是给**一个主页网址 + 账号凭据**（抖音 / 微博 / GitHub）。
> 这一层就是解决"怎么进去、读什么、读不到怎么办"。
>
> **想自己动手跑一遍**：见第 9 节，双击 `first/试一试.bat` 就行。

---

## 1. 先说结论：三种认证，按可靠性排

| 方式 | 适用 | 可靠性 | 代价 |
|---|---|---|---|
| `--token` | GitHub | ★★★ 官方 API，不会变 | 客户去建一个只读 token，1 分钟 |
| `--cookie` | 微博 / 知乎 / B 站 / 大多数站 | ★★ 取决于站点是否服务端渲染 | 客户从浏览器复制一段 Cookie |
| `--browser` | 抖音 / 微博 / 任何要交互登录的站 | ★★★ 渲染后的页面一定看得到 | 弹出窗口，客户自己登录一次 |

三种都可以，`--browser` 最通用，`--token` 最稳。

```bash
# GitHub：一条命令，不用浏览器
python first/code/collect_account.py \
    --url https://github.com/ciqiongovo --token ghp_xxx \
    --scope starred --vault-id gh-me --topic "我关注的技术" --antipode off

# 抖音 / 微博：开窗口登录
python first/code/collect_account.py \
    --url https://www.douyin.com/user/MS4wLjABAAAA... --browser \
    --vault-id dy-me --topic "我的收藏" --limit 20
```

## 2. 为什么不做"拿账号密码去 POST 登录表单"

客户说的"账号密码"，技术上最直觉的做法是：拿 `username` / `password` 去 POST 登录接口。**我们没有这么做**，三个原因都是硬的：

1. **登录接口早就不是表单了。** 抖音、微博、GitHub 现在都有设备指纹 + 验证码 + 二次验证。脚本一登就红，客户账号还可能被临时冻结 —— 演示现场翻车最难看的一种。
2. **密码落盘是所有漏洞里最贵的一种。** 一旦为了"记住登录"把密码存进配置文件，这个项目的性质就变了。比赛仓库是公开的。
3. **平台条款明确禁止把账号交给第三方程序。** 我们是产品，不是爬虫工具。

**改成了**：`--browser --username ... --password ...`

- 程序启动真实浏览器，跳到登录页；
- 把账号密码**填进输入框**（只在内存里，不落盘、不打印、不进日志）；
- 然后停住 —— **由人点"登录"、过验证码、过短信**。

效果一样（省掉打字），但密码没有离开客户的手，风控也不会因为"脚本登录"把号封了。

> 一句话给评委：**我们替客户省了打字，没有替他保管密码。**

## 3. 平台支持矩阵（都是实测的，不是推测）

| 平台 | 通道 | 实测结果 | 备注 |
|---|---|---|---|
| **GitHub** | REST API + token | ✅ **通**。`/users/{u}/starred`、`/repos`、`/search/issues` 都正常返回 | 最稳的一条路 |
| 通用站点（博客 / 专栏） | CDP 浏览器 → 抓渲染后 DOM | ✅ **通**。阮一峰博客首页抽出 15 条，抓正文 5000+ 字 | 已有 `build_vault` 做后续 |
| 微博 | CDP / Cookie | ⚠️ **未登录抽到 0 条**（跳登录页） | 登录后需再验一次 |
| 抖音 | CDP | ❌ **无头模式撞"验证码中间页"** | **必须用有头窗口**，见下 |

### 抖音这条要特别说

无头模式（`--headless`）下访问 `douyin.com`，返回的是「验证码中间页」，抽出 0 条链接。这不是代码问题，是平台的反自动化策略 —— 换成任何工具结果都一样。

**正确用法**：去掉 `--headless`，让窗口弹出来，人在里面过验证码。程序会正确识别这个状态：

```
[x] 被平台拦了：弹了验证码
    无头模式（--headless）几乎必然被拦 —— 这是实测过的，不是代码问题。
    正确做法：去掉 --headless，用有头窗口手动过验证码；
    再加 --profile <目录> 固定登录态，下次就不用重登。
```

登录态复用：

```bash
# 第一次：弹窗登录，登录态存进这个目录
python first/code/collect_account.py --url <你的主页> --browser --profile .profiles/douyin

# 之后：同一个 profile，登录态还在，不用重登
python first/code/collect_account.py --url <你的主页> --browser --profile .profiles/douyin --no-wait
```

`.profiles/` 已在 `.gitignore` 里。

## 4. 采到什么算一条

采集层只负责"**把客户账号里的东西变成候选**"，每条先有 `url` + 列表页上的标题/片段，
之后交给 `build_vault.build_item()` 逐条补正文、判立场、写省流。

```
网址 + 凭据
   │
   ├─ GitHub ────────▶ REST API ────────┐
   │                                     │
   └─ 其它 ──▶ CDP 浏览器 ──▶ 渲染后 DOM ─┤
                （登录 → 滚动 → 抽链接）  │
                                         ▼
                              raw: [{url, title, hint_text}]
                                         │
                                         ▼
                            build_item()：抓正文 → 判立场 → 省流
                                         │
                                         ▼
                          vault_<id>.json + .items.jsonl
```

**为什么要 `hint_text`**：抖音、微博的详情页要登录才看得见，抓正文经常失败。
列表页上已经有的标题和片段先存着 —— 抓不到正文时用它兜底，
否则一条已采到的内容会因为"正文没抓到"整个消失。

代码里对应 `build_item(url, backend, opts, prefetched={...})`：
片段够长就直接当正文用（省一次请求），够短就还是试一次正文。

## 7. 已知限制（答辩主动说，比被问出来强）

| 限制 | 影响 | 应对 |
|---|---|---|
| 抖音无头必被拦 | 不能全自动 | 有头 + 人工过验证码；固定 profile 复用 |
| 微博登录后未实测 | 抽多少条未知 | 现场用自己账号先跑一遍 |
| 平台改版会让选择器失效 | 抽不到 | 已做兜底：专用选择器抽不到时退回通用选择器 |
| 视频类内容正文很短 | 判不出立场 | `kind=too_short`，不参与反推荐；只进库做归档 |
| 浏览器依赖 websockets | 缺了会报错 | 只有 `--browser` 这条路需要；其它功能零依赖 |
| 知乎正文 HTTP 直连必 403 | 直接抓会整批变 `too_short` | 改在页面会话里调接口（见 7.1） |

### 7.1 知乎：正文为什么必须在浏览器里取

这是实测踩出来的，写在这里免得以后又走回去：

```
urllib 直连 https://www.zhihu.com/question/.../answer/...
  → HTTP 403（反爬/需登录）      ← 10/10 条全中
```

知乎的正文接口要求登录态，而登录态是浏览器里的 Cookie（含 HttpOnly，
`urllib` 根本读不到）。所以 `collect_zhihu.py` 改成**在页面上下文里 fetch**：

| 链接形态 | 取正文的接口 |
|---|---|
| `/question/{q}/answer/{a}` | `/api/v4/answers/{a}?include=content,question.title` |
| `zhuanlan.zhihu.com/p/{id}` | **不走接口**：直接开页面读 `.Post-RichText` |
| `/question/{q}`（热榜里常见） | `/api/v4/questions/{q}/answers?include=content&limit=3` |

专栏为什么要分出去：专栏的接口在跨子域时拿不到（`www.zhihu.com/api/v4/articles/{id}`
→ 403；切到 zhuanlan 子域再调 → 404），但**页面本身**登录后是完整渲染的，
`.Post-RichText` 里有 1 万字正文。所以专栏直接读 DOM，回答走接口。
两批分开跑 —— 混着跑会把 fetch 发到跨域地址，换回一堆 403 白等十几秒。

三条实测：同源、自动带 Cookie、返回结构化 JSON，正文 1500–2400 字；
专栏页面读 DOM 能拿 2500–10000 字。比解析列表页干净，也不怕改版。

**前提是先用 `--wait` 让人登录一次**，登录态存在 `first/.profiles/zhihu`。

热榜里给的是问题链接，接口会返回多条回答 —— 取**最长**那条：短回答常常
只有一句情绪，没有论证结构，判立场时会全军覆没。

### 7.2 两个采集入口，分工是实测逼出来的

| 入口 | 命令 | 能做什么 |
|---|---|---|
| 热榜 / 推荐流 | `--limit 10`（默认热榜） | **只做信息收集**：省流 + 原文地址 |
| 按议题搜索 | `--issue microservices_vs_monolith` 或 `--query "远程办公"` | 信息收集 **+ 反推荐** |

原因是一次实测：热榜 10 条（票房预测、教师产假、农民工欠薪、博物馆闭馆…）
与 16 个二元议题**一条都不沾边**，关键词命中全是 0，议题依据闸门把 10 条全拦了。
这不是闸门太严，是入口不对 —— 给一条时政新闻找"技术选型的对立面"，
本来就无从下手。所以热榜那条线只做信息收集；要反推荐，就按议题采集。

同一个闸门也拦掉了一批更难看的结果：修之前，模型硬把「洛阳博物馆闭馆」
判成 `monorepo_vs_multirepo`、「流浪地球票房」判成 `tofu_pudding`（豆腐脑），
反库里随即出现与原文毫无关系的反信息。现在库里会把这些站不住的立场
摘到 `stance_dropped` 里，`★` 也不再乱标。

## 9. 自己先试一遍（双击就行）

> 这是给"我有个抖音账号，想看看这东西到底能不能读出来"用的。
> 不用记主页链接，不用拼参数 —— **链接由程序从浏览器地址栏读**。

### 9.1 三步

1. 双击 `first/试一试.bat`
2. 在菜单里按 `1`（抖音）回车 —— 会弹出一个 Edge 窗口，打开 douyin.com
3. 在那个窗口里**扫码或手机号登录** → 点右上角头像进「我的主页」→ **停在那页别动**

程序每 1.5 秒看一眼地址栏，一变成 `/user/...` 就自己开始读：

```
  [√] 到主页了：https://www.douyin.com/user/MS4wLjABAAAA...
  5 秒后开始读。（要采「喜欢 / 收藏」的话，现在点那个标签）
  滚了 8 次，页面高度 4820px
  页面「xxx的主页」抽到 14 个链接
   ★  1. 为什么我不推荐初学者直接学 Rust       opinion       1832字
     2. 三分钟看完这周的更新                  too_short        41字
  ...
  入库 10 条    ★ 可参与反推荐 3 条
  → first/data/vault_douyin-10172030.json
```

4. 想接着看反推荐：`python first/code/run_vault.py --vault first/data/vault_xxx.json`

### 9.2 关于抖音，先摆清楚预期

| 你会看到 | 为什么 |
|---|---|
| 抽到的是**作品列表**，不是推荐流 | 判据是地址栏 `/user/`；没进主页不开始，避免把别人的视频当你的 |
| 想采「喜欢 / 收藏」，要在那 5 秒里点一下标签 | 标签是页面内部切换，地址栏不变，程序看不出来你切了 |
| 大部分条目标 `too_short`，不参与反推荐 | 视频详情页正文就几十个字，**没有论证结构，也就没有对立面** |
| 这是正常的，不是失败 | 反推荐只对**有观点的图文长帖**生效；短视频进来只是被归档 |

一句话：**抖音这一层验证的是"能不能读进你的账号"，不是"能不能给你找反面"。**
真正跑反推荐，用公众号 / 知乎 / 掘金 / V2EX 这类图文长帖的库。

### 9.3 抽到 0 条怎么排查

| 现象 | 先看这个 |
|---|---|
| 一直停在"还在等" | 有没有真的进到主页（点开头像、看到自己的作品墙） |
| 提示"被平台拦了：弹了验证码" | 在窗口里手动过一下，程序会继续等 |
| 主页明明有内容却抽到 0 | 平台改版了 —— 程序会退回通用选择器再试一次，仍为 0 就说明选择器要更新 |
| 浏览器弹出来，但停在空白页 | 已在向导版修掉：`/json/new` 建的是**后台标签**，窗口显示的是启动时那个 `about:blank`。现在会激活标签、并把多余的标签（含恢复出来的上次会话）关掉 |
| 提示"浏览器起来了但调试端口没响应" | 上一次的 Edge 没退干净，这次启动被转给老实例（用的是老端口）。**把多出来的那个 Edge 窗口关掉再跑**；程序本身也会自动换端口重试一次 |
| 提示"页面打不开：ERR_xxx" | 网络层问题（DNS / 代理 / 断网），不是程序。先用普通浏览器打开同一网址确认 |
| 窗口一闪就没了 | 别用 `--headless`；向导版本来就是有头窗口 |
| **按了回车，什么都没发生** | 先读 `first/.try_me.log` —— 每一步都写在里面（平台、浏览器路径、端口、当前地址、失败原因）。日志停在"浏览器已启动"就是窗口被挡/在屏幕外；停在"没等到主页"就是没走到 `user/...` 页面；有"崩溃"段就是程序自己的问题 |
| 任务栏看不到进度 | 命令行窗口的**标题**会跟着变：`正在启动浏览器` → `请在浏览器里登录…并进主页` → `已找到主页，正在读` → `完成` |

> 向导版现在的交互分工：**1–5 的平台选择在 bat（cmd）里做，Python 不再读键盘**。
> 原因：双击时 cmd 一定有控制台，而 `python` 若拿不到交互式 stdin，`input()`
> 会直接抛 `EOFError` —— 表现就是"菜单没出现 / 按回车没反应"。把选择挪到
> cmd 层，这条路上就不存在这个失败模式了。

### 9.4 登录态会留多久

第一次登录后，登录态存在 `first/.profiles/douyin/`（已在 `.gitignore`，不进仓库）。
下次直接跑，不用重登：

```bash
python first/code/try_me.py --platform douyin --no-wait
```

**它不是万能 cookie**：抖音会过期、会要求重新验证。过期就再登一次，别指望一劳永逸 ——
任何声称"一次登录永久有效"的工具，都是在替你保管一个迟早失效的凭据。

### 9.5 密码去哪了

只在你面前的那个浏览器窗口里输入。程序读的是**渲染后的页面**和**浏览器已保存的 Cookie**，
不接触你的密码，也不把 Cookie 写进仓库（除非你显式加 `--save-cookies`，那也只写到本地 gitignore 的 `cookies.json`）。
