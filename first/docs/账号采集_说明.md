# 账号采集 · 客户给一个网址和账号，怎么把他的内容读出来

> 现状：客户不再给一堆文章链接，而是给**一个主页网址 + 账号凭据**（抖音 / 微博 / GitHub）。
> 这一层就是解决"怎么进去、读什么、读不到怎么办"。

---

## 1. 先说结论：三种认证，按可靠性排

| 方式 | 适用 | 可靠性 | 代价 |
|---|---|---|---|
| `--token` | GitHub | ★★★ 官方 API，不会变 | 客户去建一个只读 token，1 分钟 |
| `--cookie` | 微博 / 知乎 / B 站 / 大多数站 | ★★ 取决于站点是否服务端渲染 | 客户从浏览器复制一段 Cookie |
| `--browser` | 抖音 / 微博 / 任何要交互登录的站 | ★★★ 渲染后的页面一定看得到 | 弹出窗口，客户自己登录一次 |

三种都可以，`--browser` 最通用，`--token` 最稳。

```bash
# GitHub：一条命令，不用浏览器
python first/code/collect_account.py \
    --url https://github.com/ciqiongovo --token ghp_xxx \
    --scope starred --vault-id gh-me --topic "我关注的技术" --antipode off

# 抖音 / 微博：开窗口登录
python first/code/collect_account.py \
    --url https://www.douyin.com/user/MS4wLjABAAAA... --browser \
    --vault-id dy-me --topic "我的收藏" --limit 20
```

## 2. 为什么不做"拿账号密码去 POST 登录表单"

客户说的"账号密码"，技术上最直觉的做法是：拿 `username` / `password` 去 POST 登录接口。**我们没有这么做**，三个原因都是硬的：

1. **登录接口早就不是表单了。** 抖音、微博、GitHub 现在都有设备指纹 + 验证码 + 二次验证。脚本一登就红，客户账号还可能被临时冻结 —— 演示现场翻车最难看的一种。
2. **密码落盘是所有漏洞里最贵的一种。** 一旦为了"记住登录"把密码存进配置文件，这个项目的性质就变了。比赛仓库是公开的。
3. **平台条款明确禁止把账号交给第三方程序。** 我们是产品，不是爬虫工具。

**改成了**：`--browser --username ... --password ...`

- 程序启动真实浏览器，跳到登录页；
- 把账号密码**填进输入框**（只在内存里，不落盘、不打印、不进日志）；
- 然后停住 —— **由人点"登录"、过验证码、过短信**。

效果一样（省掉打字），但密码没有离开客户的手，风控也不会因为"脚本登录"把号封了。

> 一句话给评委：**我们替客户省了打字，没有替他保管密码。**

## 3. 平台支持矩阵（都是实测的，不是推测）

| 平台 | 通道 | 实测结果 | 备注 |
|---|---|---|---|
| **GitHub** | REST API + token | ✅ **通**。`/users/{u}/starred`、`/repos`、`/search/issues` 都正常返回 | 最稳的一条路 |
| 通用站点（博客 / 专栏） | CDP 浏览器 → 抓渲染后 DOM | ✅ **通**。阮一峰博客首页抽出 15 条，抓正文 5000+ 字 | 已有 `build_vault` 做后续 |
| 微博 | CDP / Cookie | ⚠️ **未登录抽到 0 条**（跳登录页） | 登录后需再验一次 |
| 抖音 | CDP | ❌ **无头模式撞"验证码中间页"** | **必须用有头窗口**，见下 |

### 抖音这条要特别说

无头模式（`--headless`）下访问 `douyin.com`，返回的是「验证码中间页」，抽出 0 条链接。这不是代码问题，是平台的反自动化策略 —— 换成任何工具结果都一样。

**正确用法**：去掉 `--headless`，让窗口弹出来，人在里面过验证码。程序会正确识别这个状态：

```
[x] 被平台拦了：弹了验证码
    无头模式（--headless）几乎必然被拦 —— 这是实测过的，不是代码问题。
    正确做法：去掉 --headless，用有头窗口手动过验证码；
    再加 --profile <目录> 固定登录态，下次就不用重登。
```

登录态复用：

```bash
# 第一次：弹窗登录，登录态存进这个目录
python first/code/collect_account.py --url <你的主页> --browser --profile .profiles/douyin

# 之后：同一个 profile，登录态还在，不用重登
python first/code/collect_account.py --url <你的主页> --browser --profile .profiles/douyin --no-wait
```

`.profiles/` 已在 `.gitignore` 里。

## 4. 采到什么算一条

采集层只负责"**把客户账号里的东西变成候选**"，每条先有 `url` + 列表页上的标题/片段，
之后交给 `build_vault.build_item()` 逐条补正文、判立场、写省流。

```
网址 + 凭据
   │
   ├─ GitHub ────────▶ REST API ────────┐
   │                                     │
   └─ 其它 ──▶ CDP 浏览器 ──▶ 渲染后 DOM ─┤
                （登录 → 滚动 → 抽链接）  │
                                         ▼
                              raw: [{url, title, hint_text}]
                                         │
                                         ▼
                            build_item()：抓正文 → 判立场 → 省流
                                         │
                                         ▼
                          vault_<id>.json + .items.jsonl
```

**为什么要 `hint_text`**：抖音、微博的详情页要登录才看得见，抓正文经常失败。
列表页上已经有的标题和片段先存着 —— 抓不到正文时用它兜底，
否则一条已采到的内容会因为"正文没抓到"整个消失。

代码里对应 `build_item(url, backend, opts, prefetched={...})`：
片段够长就直接当正文用（省一次请求），够短就还是试一次正文。

## 5. 采集结果长什么样

GitHub 通道（实测输出）：

```json
{
  "title": "ciqiongovo/antipode",
  "kind": "repo",
  "summary": "对跖点 Antipode —— 反推荐 × 信息筛选：既给你想看的，也给你该看的。TECHATHON 2026 参赛项目。（Python · 0 star）",
  "url": "https://github.com/ciqiongovo/antipode",
  "antipode_eligible": false
}
```

注意 `antipode_eligible: false` —— **GitHub 类内容默认不开反推荐**。
代码仓库、邮件、issue 是工作材料，没有"对立面"，硬找只会得到抬杠。
这一点和之前定下的开关策略一致（`--antipode off`）。

## 6. 现场怎么演示（3 分钟）

最稳的顺序：**先用 GitHub，再讲抖音为什么必须人工登录**。

```bash
# 1. 一条命令：账号 → 库（30 秒）
python first/code/collect_account.py \
    --url https://github.com/<你的账号> --token <只读 token> \
    --scope starred --vault-id demo-gh --topic "我 star 过的"

# 2. 库 → 反库（沿用原有链路）
python first/code/run_vault.py --vault first/data/vault_demo-gh.json
```

抖音 / 微博这段**不要现场登**（要过验证码，还可能是客户私人账号）。录屏或者口述：

> "抖音和微博必须登录才看得见，我们让客户在自己的浏览器窗口里登一次，
> 我们不碰密码。登进去之后，页面上的东西我们就能读 —— 因为读的是他看到的那个页面。"

## 7. 已知限制（答辩主动说，比被问出来强）

| 限制 | 影响 | 应对 |
|---|---|---|
| 抖音无头必被拦 | 不能全自动 | 有头 + 人工过验证码；固定 profile 复用 |
| 微博登录后未实测 | 抽多少条未知 | 现场用自己账号先跑一遍 |
| 平台改版会让选择器失效 | 抽不到 | 已做兜底：专用选择器抽不到时退回通用选择器 |
| 视频类内容正文很短 | 判不出立场 | `kind=too_short`，不参与反推荐；只进库做归档 |
| 浏览器依赖 websockets | 缺了会报错 | 只有 `--browser` 这条路需要；其它功能零依赖 |
